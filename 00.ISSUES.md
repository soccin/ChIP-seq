## Open

**#1 b37 is supported but untested on IRIS** (spec D18) · `risk`
`high` — No b37 ChIP data was available for v1.0.0, so acceptance item
17 of the spec was not run. Build test data (the reads of three GRCh38
test BAMs, `samtools fastq`, mapped with PEMapper `human_b37`), run a
complete pipeline on it, and check that `annotateWithHomer.sh` adds
`chr` and annotates most peaks and that `diffAnalysisPairwise.R` runs.

**#2 `deliverResults.sh` not ported** (spec D6) · `enhancement`
`medium` — It still prints JUNO paths and the delivery URL of the old
server. How to port it, following the adagio delivery on IRIS, is in
`POST-IRIS-PORT.md`. Same as ATAC-seq issue #1.

**#3 Rename ATAC-seq's `b38` tag to `hg38`** · `cleanup` `medium` —
This repo names GRCh38 `hg38`, the name the Broad and UCSC use. Done on
ATAC-seq branch `fix/genome-tags` (f48b292, not yet merged), which copied
this repo's `bin/getGenomeBuildBAM.sh`; the two are byte-identical
(checked 2026-10-11) and must stay so. Close when that branch is merged
to ATAC-seq master.

**#4 Restore `-o|--outdir`** (spec D2) · `enhancement` `low` — Removed
in v1.0.0 because `qc_ChIPSeq_01.R`, `qc_ChIPSeq_02.R`,
`R/diffAnalysisPairwise.R`, `postPipe.sh` and the run records all assume
`out/`. Restore it only once every one of them takes the output
directory from the run record instead.

**#5 Hybrid genomes** (spec D17) · `enhancement` `low` — `mm10+b37` was
dropped in v1.0.0 (no IRIS reference produces it, and what the pipeline
did with its human contigs was never checked). The IRIS `hg38+mm39`
hybrid (PEMapper `human_hg38+mm39`, mouse contigs named `MM39_chr*`) is
recognized by name and refused. Supporting it needs a design: which
species a run analyzes, and which genome file, MACS genome size and
annotation go with it.

**#6 Merge the three `postMapBamProcessing_*` scripts** (spec D9) ·
`cleanup` `low` — Default, `_NoPP` and `_SE` share all but their filter
flags and the fixmate step. Merging them is a behavior change that needs
its own validation (compare outputs of all three modes before and
after).

**#7 The SAF starts one base early** · `bug` `low` `pre-port` —
`mergePeaksToSAF.sh` writes the 0-based `bedtools merge` start into the
1-based SAF, so featureCounts counts one extra base at the left edge of
every peak. Fixing it changes the counts. Checks A and B test the same
intervals as featureCounts, so they are not affected.

**#8 Early exits write no status file** (ATAC-seq #9) · `enhancement`
`low` — A bad option, `usage`, the `SBATCH_SCRIPT_DIR` check and the venv
check exit before the `EXIT` trap is installed. `checkRun.sh` reports
`NONE`; the reason is only in the control log. Leave out
`checkPreviousRun`: a run it refuses must not write the status file,
which belongs to the earlier run.

**#9 Old runs cannot be classified once `sacct` forgets the control
job** (ATAC-seq #10) · `enhancement` `low` — Stage logs end with
`#CHIP_EXIT=<rc>`, but the control log has no trailer. Fix in both
repos together.

**#14 Mitochondrial reads are dropped before peak calling** · `risk`
`low` `pre-port` — POST keeps only the contigs of
`lib/genomes/<TAG>.genome` (autosomes, X, Y), so chrM/MT reads never
reach MACS2. v0.9.0 did the same (its `@SQ` regex kept only `1`-`9`,
`X`, `Y` and their `chr` forms). ENCODE's ChIP-seq pipeline keeps chrM
through peak calling (`filter_chrs=[]`) and removes chrM only from the
final filtered peaks; its ATAC-seq pipeline removes it before peak
calling (links in `../ATAC-seq/docs/GENOMES.md`). The difference changes
the read totals MACS2 uses to scale the control, so peak calls can
differ slightly from ENCODE's. Decide whether to keep the current behavior (and say so in
`docs/output.md`) or follow ENCODE. ATAC-seq now uses the same genome
files, so the decision applies to both repos. The `filter(Chr != "MT")`
in `R/diffAnalysisPairwise.R` has nothing to remove and does not cover
`chrM`; it can go once this is decided.
