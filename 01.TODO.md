## 1. `-o|--outdir` is a lie downstream

`pipe.sh` honors `$ODIR` throughout, but everything after it hardcodes `out`:

- `qc_ChIPSeq_01.R:9` - `dir_ls("out/macs", ...)`
- `qc_ChIPSeq_02.R:28,67` - `read_tsv("out/macs/...")`
- `R/diffAnalysisPairwise.R:177` - `dir_ls("out/macs", ...)`

Run `pipe.sh -o results ...` and the pipeline completes, then `postPipe.sh
results` moves the BAMs correctly and the QC silently finds nothing. v0.9.0
papers over this with a warning in the usage text; the real fix is to thread
the output directory through as an argument (or an env var read by all three R
scripts) and drop the caveat.

While in there: `pipe.sh`'s closing banner hardcodes `ChIP-seq/postPipe.sh out`
regardless of `-o`, and prints a line that reads `$ODIR=out` inside an
unquoted heredoc, so it expands to `out=out`. That was presumably meant to be
literal text.

## 2. Temp directories are never cleaned up

All three post-processing scripts create `_scratch_ChIPSeq/<uuid>` and then
never remove it - the cleanup line is commented out:

- `postMapBamProcessing_ChIPSeq.sh:74` - `#rm -rf $TDIR`
- `postMapBamProcessing_ChIPSeq_NoPP.sh:63` - `#rm -rf $TDIR`
- `postMapBamProcessing_ChIPSeq_SE.sh:54` - `#rm -rf $TDIR`

The default script at least deletes its `step*.bam` files inline; the SE and
NoPP variants delete nothing, so every run leaves a full set of intermediate
BAMs behind. Note `TDIR` is a *relative* path, so these pile up in whatever
directory the job ran from, not in scratch. This is a real disk leak on a
shared filesystem.

Check for accumulated `_scratch_ChIPSeq` dirs in old project directories
before fixing, there may be a lot to reclaim.

## 3. MACS exit status is never actually checked

`callPeaks_ChIPseq.sh` has `set -e` at line 4 and then:

    MACS_ERROR=$?      # line 134
    exit $MACS_ERROR   # line 136

If `macs2 callpeak` fails, `set -e` exits before line 134 is reached. If it
succeeds, `$?` is 0. So `MACS_ERROR` is always 0 and this error handling does
nothing. Either drop it or capture the status properly (`|| MACS_ERROR=$?`).

## 4. Genome support is inconsistent across the pipeline

`getGenomeBuildBAM.sh` recognizes about eleven builds by `@SQ` md5, but:

- `callPeaks_ChIPseq.sh:37-50` and `makeBigWigFromBEDZ.sh:26-38` accept only
  `mm10*` and `b37`
- `lib/genomes/` contains only b37, mm10, mm10+b37, mouse_mm10

A BAM that resolves to `hg19`, `GRCh37-lite`, `mm9Full`, or `GRC_m38` passes
the up-front check in `pipe.sh` and then fails several hours into the run.
Either validate the detected build against what is actually supported at
startup, or add the missing builds. Adding one means touching the md5 case
statement, both downstream case statements, and `lib/genomes/`.

Related: `annotateWithHomer.sh` is hardcoded to hg19 regardless of the
detected genome. It prints a warning, but it should take the build as an
argument.

## 5. Hardcoded paths

- `annotateWithHomer.sh:4` - HOMER pinned to a personal directory under
  `/juno/bic/work/socci/opt/...`
- `callPeaks_ChIPseq.sh:83-87` - `TMPDIR` set to `/fscratch/socci` or
  `/scratch/socci`
- `lsf.sh:1` and `bin/bSync:3` point at two *different* LSF installs
  (`/admin/lsfjuno/lsf/10.1/...` vs `/common/juno/OS7/10.1/...`). At least one
  is probably wrong or stale; they should agree and be resolved once.

## 6. R scripts are not self-contained

- `qc_ChIPSeq_01.R:7` and `qc_ChIPSeq_02.R:21` do
  `source("ChIP-seq/tools.R")` with a hardcoded relative path, so the repo
  checkout has to be named exactly `ChIP-seq` and sitting in the project
  directory. Use `SDIR`-style self-location instead.
- `len()` is used in four R scripts and defined nowhere in the repo; it comes
  from `~/.Rprofile`. Anyone else running these gets "could not find function
  len". Either vendor it into `tools.R` or replace with `length()`.

## 7. Sample matching in `generateMACSArgs.R` is prefix-based

Targets and controls are matched with `grep(paste0(name, "_.*postProcess"))`,
so a sample whose name is a prefix of another sample's name matches both and
aborts the run as "degenerate target/control". Anchor the match or require an
exact sample-name field.

## 8. Version has no single source of truth

v0.9.0 had to be updated by hand in five places (`README.md`, `VERSION.md`,
`CHANGELOG.md` plus its compare links, `docs/output.md`, and the `cat()`
banner in `getPackageVersions.R`), and had already drifted to 0.8.0/0.7.x
before that. Derive it from one file, or from `git describe` the way `pipe.sh`
already does.

## 9. Doc rendering is not reproducible

`docs/output.html` and `docs/output.pdf` are generated from `docs/output.md`,
but the command that produces them is not recorded anywhere. Add a Makefile
target so the renders can be regenerated without guessing at pandoc options.

## 10. No tests

There is no test suite, linter, or CI. Verification today is `bash -n` plus
reading the code. A smoke test over a small BAM pair that runs the full stage
sequence would catch most of the above.
